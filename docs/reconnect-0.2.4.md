# 重试等待期间的迟到连接检测

## 问题

0.2.3 将单调时钟退避检查放在工作循环的状态查询之前。
这可以避免控制接口故障时每三秒重复查询，但同时也暂停了普通握手失败后的健康检查。

`swanctl --initiate --timeout` 的超时含义是停止等待并退出，后台 charon 的握手仍可能继续。
如果隧道在命令返回后建立，旧后台可能直到当前退避期结束才发现它已经可用，额外延迟最多约 300 秒。
界面还会将正在握手和等待下一轮重试都标记为“等待重连”，难以判断后台究竟在做什么。

参见 [strongSwan 的命令说明](https://docs.strongswan.org/docs/latest/swanctl/swanctlInitiate.html)。

## 0.2.4 的处理

- 区分普通握手退避与控制接口异常退避。
- 普通握手等待期间继续约每三秒检查 SA；连接已建立时立即清除等待时间和旧失败信息。
- 健康查询发现隧道仍未建立时，等原定重试时间再发起握手，不制造重复连接。
- 控制查询本身异常时，保留指数退避，避免循环访问失效的控制接口。
- 新一轮握手开始时清除倒计时，将界面显示为“重新连接中”。
- 失败阶段使用固定枚举和提示，不将原始握手输出、用户名或秘密放入状态接口。

## 验证与边界

新增回归模拟命令超时后，隧道在一秒退避期内自行建立。
该回归在 0.2.3 源码上失败，在修复后通过；连接被发现时退避期尚未结束，也没有重复握手或重启其他线路。
既有控制故障退避、认证失败暂停、并发隔离与断开测试继续通过。

此修复不保证解决网关不下发地址配置、服务器会话限制或链路丢包。
“未收到网关的地址配置响应”仅表示客户端未观察到响应，仍需结合对端日志或故障期间的报文证据定位根因。
短时、恢复阶段的保活观察不能证明此前故障期间没有丢包。
